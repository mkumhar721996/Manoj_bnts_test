6. Open questions

Blocking items first — these should be confirmed before implementation locks in the assumed behaviour.

Promo code field: only the "applied" success state is designed

Blocking

This story is specifically about promo code application, but the frame only shows ONE state of PromoCodeField (13:362–13:370): a code already typed in, validated, with a green border/check icon and a solid-green "Applied" pill button. No default (empty, pre-submit), invalid-code, or loading state is drawn.

  • Derive default/error states from existing tokens — neutral #EBE7DF border for empty, brand red #C82D25 for error
  • Request the designer add explicit empty/error/loading frames for this component before building it
Assumption appliedBuilt default (empty input, neutral border, outline "Apply" button) and error (red border, inline error text, button reverts to "Apply") states by extension of the existing token palette, keeping the drawn applied state pixel-faithful.

Two different delivery-time estimates shown on the same screen

Non-blocking

The header shows "Estimated delivery: 30 mins" (13:258) while the Delivery Destination card shows "Est. Delivery: 25-35 mins" (13:328). Could be two distinct metrics or a design inconsistency.

Assumption appliedTreated as two distinct, intentional data points — a general site ETA in the header vs. a range specific to the entered delivery address — wired to separate props.

No hover/focus state drawn for inactive nav links

Non-blocking

"Home" and "Our Menu" are only shown in resting white-text state; only "Cart" shows the active red-underline treatment.

Assumption appliedAssumed a color shift to brand red on hover for inactive links, matching the active-state color, with no separate focus-ring token defined.

Quantity stepper behaviour at minimum quantity

Non-blocking

No state shows what "-" does at quantity 1 — decrement to 0 and auto-remove, disable the button, or clamp at 1.

Assumption appliedAssumed "-" at quantity 1 removes the line item (equivalent to pressing "Remove"), since no disabled-button state is drawn.

Footer social icons have no link targets in the Figma data

Non-blocking

Instagram/Facebook/Twitter icon buttons are visual-only nodes; no URLs are attached in the design file.

Assumption appliedLeft href values as placeholders ("#") pending real social profile URLs.
